# Graph context mini-evaluation

Raw results: `graph_eval_20261125_152620_112169.json`.
Detailed AI-assisted review: `graph_eval_20261125_152620_112169.review.json`.

## Setup

- Five English development questions, two arms per question.
- Same frozen title-aware/vector top-3 papers, abstracts, question and instructions.
- Only the graph-enriched arm receives the extracted graph facts.
- Same Qwen model, temperature 0, seed 42, context 8192 and output cap 256 tokens.
- Arm order alternates. Saved prompt pairs were checked to differ only in facts.
- Reference answers are not sent to the model.

## Results

| Item | Retrieval only | Graph enriched |
|---|---|---|
| Completed calls | 5/5 | 5/5 |
| Truncated answers | 0 | 0 |
| Mean generation wall time | 28.6 s | 47.4 s |
| Answerable responses with a retrieved-source URL | 1/4 | 1/4 |

The expected article was retrieved for all four answerable questions (hit@3:
4/4). Both modes correctly abstained on the GPU-price question.

No clear difference in core answer quality was observed across the five cases.
Both modes made the same numerical interpretation error: the Bioformer abstract
says **40% of the comparator's parameters**, not **40% fewer parameters**.
The MAP and Recall@100 improvements were quoted correctly.

## Conclusion and limitations

Adding graph facts did not demonstrate an answer-quality benefit on this small
sample and increased generation wall time in this run. The questions mostly
require one abstract, not multi-hop reasoning. This does not establish that
graphs are generally useless.

This review was performed by the AI assistant involved in development, not an
independent blinded reviewer. It is not a held-out benchmark. Citation presence
does not establish citation support, and timing includes cache/loading effects.
No graph data or default retrieval mode was changed as a result of this review.
